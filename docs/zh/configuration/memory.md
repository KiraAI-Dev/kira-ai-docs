# 记忆设置

KiraAI v3 将 **LLM 上下文**与**实际收发消息历史**分开保存和清理。长期记忆插件维护的核心记忆又是另一种数据，不等同于这两者。

## 三类数据

| 数据 | 用途 | 管理方式 |
| --- | --- | --- |
| LLM 上下文 | 发给模型的用户、助手和工具消息，按轮次组织成分块 | 在会话详情的 **LLM 上下文**中查看和编辑；长度由聊天设置控制 |
| 历史消息 | 实际收发消息链、发送者、媒体、方向和发送状态 | 在会话详情的 **历史消息**中查看；按独立保留策略清理 |
| 长期记忆 | 由记忆插件提炼并提供给模型的信息 | 通过对应插件的工具和配置管理 |

上下文被裁剪后，已保存的历史消息仍可存在；历史被清理后，也不会因此裁剪 LLM 上下文。上下文条目或分块数量不能当作平台消息数量。

## 上下文长度

在 **配置项 → 数字生命 → 聊天设置**中配置：

- `max_memory_length`：默认保留 10 个上下文分块。一轮处理可包含多条消息，尤其是存在多次工具调用时。
- `memory_overflow_discard_count`：默认每次丢弃 1 个最早分块。超过上限较多时，会额外移除溢出的分块以恢复到上限。

上下文会影响模型输入量、响应时间和费用。详细说明见[聊天设置](./chat)。

## 历史清理

在 WebUI 配置页的消息历史清理区域调整以下设置，对应运行时配置 `bot_config.message_history_cleanup`：

```json
{
  "enabled": true,
  "max_age_days": 0,
  "max_messages_per_session": 500,
  "cleanup_interval_seconds": 3600
}
```

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 启用定期清理 |
| `max_age_days` | `0` | 为 0 时不按保存天数限制 |
| `max_messages_per_session` | `500` | 每个会话最多保留的历史记录数量 |
| `cleanup_interval_seconds` | `3600` | 清理任务检查间隔，单位为秒 |

清理会回收不再被引用的存档媒体。一般会话媒体存档位于 `data/session_media/archive/`，不要把整个目录当作普通临时文件删除。

## 从 v2 或早期 v3 升级

升级前停止 KiraAI 并备份整个 `data/` 目录。

会话管理器首次初始化时，将 `data/memory/chat_memory.json` 导入数据库中的 `chat_sessions`，并通过 `database_migrations` 记录完成状态。已有数据库会话不会被旧文件覆盖；导入完成后，后续启动不会重新导入。

旧 JSON 文件会保留，但不再实时更新。不要通过编辑它修改当前会话，也不要仅备份该文件来保存 v3 的最新上下文。无效的顶层 JSON 会导致导入报错，应先检查日志并修复原数据。

插件开发者还需要将会话接口迁移为异步，并显式保存快照修改，见 [PluginContext API](../development/plugins/context#会话读写与能力覆盖)。

## 清空时的区别

- 会话中的 **清空 LLM 上下文**只清空模型上下文，保留已存档消息。
- 网页聊天中的删除记录操作删除其独立聊天存档和媒体，保留聊天设置与 LLM 上下文。
- 历史清理策略只管理结构化历史及无引用媒体，不影响长期记忆插件中的内容。
